# Impact log

The list deliberately uses **no analytics, no tracking pixels, and no short links**. That means impact has to be recorded qualitatively, from things people tell you or publish.

Record an entry when:

- Someone cites the list in a paper, report, syllabus, or training deck.
- A helpline, newsroom, or NGO confirms they use the handout.
- A translator publishes a translation.
- A maintainer says the list sent them users or contributors.
- A directory accepts the list.
- A correction changes practice (for example, a tool description that was misleading).

Do **not** record: stars, clones, or raw traffic as impact. They measure attention, not use.

## Types

- `Citation` — academic or technical publication.
- `Training` — workshop, course, or helpline script.
- `Directory` — awesome list or index.
- `Contribution` — translation, correction, or new maintainer.
- `Press` — reporting that references the list.
- `Community` — forum, subreddit, or chat post.

## Review cadence

Quarterly, alongside the link and staleness pass:

1. Add any missing entries with evidence.
2. Remove claims that can no longer be verified.
3. Summarise the quarter in one paragraph for grant or partner conversations.
4. Never include identifying details about targeted individuals.

## Citing

If someone asks how to cite the list, point them to `CITATION.cff` and the repository URL. Ask them to include an access date, because entries change.
